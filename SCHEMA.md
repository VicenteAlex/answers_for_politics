## Common columns of every Markdown entity
Columns shared by every Markdown entity (all md tables also expose these).
- `id` id* — Unique id; must equal the file name without .md
- `type` enum* [dossier|history|knowledge|measure|program|question|statement|study|vote_note] — Entity type; selects the md table
- `title` text*
- `summary` text* (≤400 chars) — 1-2 neutral sentences, used for cheap triage
- `lang` enum* [es|en|ca|eu|gl|fr|de|it|pt|other] — Language of the body
- `date` date — Date of the fact (not of collection)
- `date_precision` enum [day|month|year] — Granularity of date; partial dates use the 1st day
- `jurisdiction_id` id → jurisdictions — Who acted / where it applies; level is derived from it
- `verification` enum [primary|secondary|unverified|disputed] — primary = checked against the official/original source
- `context_note` text (≤300 chars) — Optional. Verifiable facts only, cited, no adjectives or judgements
- `created` date*
- `updated` date*
- list `topics` → entity_topics: list of topic_id values, or mappings with keys ['topic_id']
- list `actors` → entity_actors: list of party_id values, or mappings with keys ['party_id', 'role']
- list `citations` → citations: list of url values, or mappings with keys ['url', 'source_id', 'title', 'accessed', 'archive_url', 'locator']
- list `related` → entity_relations: list of related_id values, or mappings with keys ['related_id', 'relation']

## Built objects
- `entities` (view) — id, type, title, summary, date, jurisdiction_id, path, updated: every entity of every table.
- `documents` (table) — id, type, lang, title, summary, body, path: the searchable text (`kb search`).

## Views
- `vote_results` — Vote counts per (vote, parliamentary group, party), computed from vote_casts. Party attribution is our own (elaboración propia).
- `v_governments` — Governments with head's name and governing / supporting parties. A partner that joined late or left early shows its dates, e.g. "es-vox (2023-07-11→2024-07-11)".
- `v_entity_context` — Each dated entity with the local, regional and state government in office on its date (ASOF join).
- `v_vote_party` — Position of each party in each vote (summed over groups). split = the party's deputies did not all vote alike.
- `v_party_actions` — Everything a party did: its position in each vote plus every entity where it appears as actor (author, implementer...).
- `v_promises` — Promises with party, election and number of evidence links.
- `v_claims` — Knowledge claims with counts of supporting / contradicting studies and best evidence grade (A best).
- `v_indicators` — Observations joined with their definition (name, unit, nominal/real, source).
- `v_topic_entities` — Entities per topic including sub-topics (use: WHERE root_topic = 'housing').

## Example queries
```sql
-- Who governed Spain and Catalonia on a date (shortcut: kb context 2023-05-24 --jurisdiction es-ct)
SELECT jurisdiction_id, head_name, governing_parties, support_parties FROM v_governments
WHERE jurisdiction_id IN ('es', 'es-ct') AND DATE '2023-05-24' BETWEEN valid_from AND coalesce(valid_to, DATE '9999-12-31');

-- How each party voted on housing votes, with the state government at the time
SELECT vp.date, vp.title, vp.object, vp.bundled, vp.party_id, vp.position, c.state_governing_parties
FROM v_vote_party vp
JOIN v_topic_entities te ON te.id = vp.vote_id AND te.root_topic = 'housing'
JOIN v_entity_context c ON c.id = vp.vote_id
```
